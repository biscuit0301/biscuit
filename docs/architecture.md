# 架构与扩展

数据提供方 → `data.load_bars` → `features.build_features` → `TradingEnv` → 策略 → `backtest` / `paper`。

默认包无外部运行时依赖，方便离线调试。核心环境不依赖 Gymnasium；`envs/gymnasium.py` 是可选适配层，基础策略和 PPO 使用同一套账户与成交逻辑。策略协议仅接收观察向量，降低意外读取未来数据的风险。

观察日 `t` 的特征只依赖 `0..t`。环境从 `lookback` 索引开始观察，第一次成交在 `lookback+1`；最后一条行情只执行此前的信号并进行估值。奖励是当日权益相对上一估值日的净收益率，包含隔夜跳空、当日价格变动及执行费用。

每个交易日仅有一个目标仓位调仓动作，所以当天新买的股票无法当天再次卖出。增加盘中事件后必须改为明确的可卖持仓/冻结持仓账本，不能继续依赖日频时序满足可卖约束。

满仓目标受整手、费用与滑点约束，实际仓位可能偏离 100%。买入数量按现金重新约束；卖出收取佣金和配置的卖出税费。浮点数用于研究骨架，接实盘前应采用明确的货币和价格精度处理。

扩展建议：

1. 在 `data/` 下增加数据源适配器，统一输出经过校验的 Bar；记录来源、下载时间、证券身份及规则版本。
2. 将多资产现金/持仓管理和撮合从环境拆出，保留策略、回测、模拟交易共用成交引擎。
3. 在 `strategies/` 新增 `predict(observation)` 策略；如果需要循环网络，显式管理隐藏状态和 episode 边界。
4. 为多资产、盘中、公司行为及真实交易规则添加数据契约和针对性回归测试后，再扩展训练任务。

不包含实时服务、外部发送消息、账户凭证或实盘订单接口。无自动交易发布步骤。
