# 单资产日线数据契约

CSV 使用 UTF-8，可带 BOM，列顺序必须如下：

```csv
date,open,high,low,close,volume,can_buy,can_sell
2024-01-02,10.0,10.2,9.8,10.1,100000,1,1
2024-01-03,10.1,10.3,10.0,10.2,110000,1,1
```

上面两行仅说明格式，实际回测至少需要 `lookback + 2` 行。

| 字段 | 要求 |
| --- | --- |
| date | `YYYY-MM-DD`，唯一、严格升序，不自动排序或去重 |
| open/high/low/close | 有限正数，满足 OHLC 高低范围关系 |
| volume | 有限非负数；零表示不能成交，本模型不限制参与率 |
| can_buy/can_sell | 严格为 `0`/`1`；表示本模拟执行时点允许该方向成交 |

一个文件仅代表一个证券。执行价格应采用一致的实际价格口径；不能简单用后复权/前复权价格成交，却不调整账户的现金和股份。当前模型没有公司行为处理，跨除权除息的真实数据需先实现相应账户事件。

标记由数据适配器结合当时规则提供。日线 OHLCV 本身不能证明开盘排队可成交，也无法准确模拟涨跌停撮合；即使标记为允许，本模型也只是理想化全量成交。不要将回看全天价格后产生的可成交标记作为策略输入。

生成器只过滤周末，不处理真实节假日，不代表真实证券、交易日历或实际价格限制。原始数据和处理数据默认被 Git 忽略；项目不包含供应商密钥和受限行情。
